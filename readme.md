# カオス小説

一人一冊、一度きりの原稿を末尾へ継ぎ足していく共同小説アプリです。本文表示と原稿入力の両方を縦書きにしています。

現在は動作確認用に**デフォルトで管理者モード**です。管理者は本を何冊でも作成でき、同じ本へ何度でも投稿でき、本とその投稿履歴を削除できます。一回1〜400字と本の文字数上限・完結ルールは維持します。投稿後は「次の一節を書く」で入力欄を空にして続きを書けます。直前の投稿原稿は結果欄から確認できます。

ログイン認証はなく、このサーバーに接続する全員を管理者として扱います。一般参加の挙動を試す場合は `$env:ADMIN_MODE = '0'` を設定してサーバーを再起動してください。通常モードでは従来の一冊一回制限が働き、削除APIも拒否されます。クライアントから管理者権限を指定することはできません。

## 起動

Node.js **22.13以上** と npm が必要です。検証環境は Windows / Node.js 22.18.0。Node.js 22では組み込みSQLiteの実験的API警告が表示されます。

```powershell
npm ci
npm start
```

http://127.0.0.1:3000 を開きます。`npm start` はブラウザ用JavaScriptをビルドしてからサーバーを起動します。

ポートを変更する場合：

```powershell
$env:PORT = '3100'
npm start
```

`npm run dev` はサーバーを監視して再起動します。フロントエンドのJavaScript変更後は別ターミナルで `npm run build` を実行し、ブラウザを再読込してください。CSSはビルド不要です。

## 設定と保存先

`.env.example` に設定例があります。`.env` の自動読込は行いません。シェルまたはサービスの環境変数で指定します。

| 変数 | 初期値 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 待受アドレス |
| `PORT` | `3000` | 待受ポート |
| `DB_PATH` | `./data/novels.sqlite` | SQLiteファイル（起動ディレクトリ基準） |
| `PUBLIC_ORIGIN` | リクエストの `http://Host` | HTTPSリバースプロキシ利用時の公開元。末尾スラッシュなし |
| `COOKIE_SECURE` | 未設定 | HTTPS利用時は `1` |
| `ADMIN_MODE` | `1`相当 | `0`で通常モード。それ以外・未設定は管理者モード |

初回起動時に保存先ディレクトリを作成し、`schema.sql` によりバージョン2のDBを初期化します。既存のバージョン1は `migrations/002-admin.sql` で起動時に自動移行します。本・本文・参加者・冪等性キーは保持し、既存投稿は通常投稿として引き継ぎます。

本、投稿、匿名参加者IDはサーバーDBに保存され、再起動後も残ります。バックアップはサーバー停止後にDBファイルをコピーしてください。実行中のWALファイルを無視して本体だけコピーしないでください。`data/` とDBファイルはGit管理対象外です。

初期版は**単一Node.jsプロセス＋ローカル永続ディスク**で動かす構成です。複数人は同じサーバーへ接続します。複数台のサーバーに別々のSQLiteファイルを配置した構成や、永続ディスクのないホスティングは対象外です。別端末から試す場合はアクセス可能な待受アドレスを設定し、同じホスト名・URLを共有してください。

## 確定した扱い

- AGENTS.md第10節の荒らし対策は、ユーザー判断により今回の対象外です。文章らしさの判定、禁止語、AI修正はありません。
- 空白のみ・1文字の原稿も許可します。空文字と401文字以上は拒否します。
- 改行はCRLF/CRをLFに統一します。書記素単位で投稿ごとに文字数を計算し、**各投稿の掲載文字数の合計**を本の文字数とします。投稿同士を連結して再計算しません。
- 書記素分割はクライアント・サーバーで同じ固定バージョンの `graphemer 1.4.0` を利用します。実装のUnicode規則は同ライブラリのUnicode 15準拠です。将来ライブラリを更新する際も、保存済み投稿の文字数を勝手に再計算しない方針です。
- 最後の投稿は残量に収まる先頭の書記素だけを掲載します。「終わり」と書いても文字数上限未満なら完結しません。

## 採用した暫定判断

- ログイン不要。サーバーがランダムな匿名IDを発行し、HttpOnly / SameSite=Lax Cookieで1年間保持します。
- 作成操作では投稿権を消費しません。タイトルは1〜100字、空白だけは不可。タイトル・長さ・個別投稿の編集削除UIはありません。管理者は本全体を確認ダイアログ経由で削除できます。
- 読書は横方向スクロール方式です。3秒ごとの更新確認で通知し、「本文に反映」を押すまで本文DOMを更新しません。反映時もスクロール位置を保持します。
- 原稿と送信中のキーを小説ごとにlocalStorageへ保存します。通信エラーでは同じキー・同じ原稿で再送できます。送信中の原稿は変更不可ですが、選択・コピーできます。通信は15秒でタイムアウトし、結果が不明な場合も再送できます。
- 投稿成功後も原稿を保持し、一部掲載時は未掲載部分を表示します。Cookieと端末の保存領域は独立しています。
- 明朝体は利用端末の游明朝・ヒラギノ明朝等をCSSで指定し、serifへフォールバックします。フォントファイルは配布・外部取得しません。紙の質感はCSSのみです。

## 投稿の整合性

`store.js` の `BEGIN IMMEDIATE` トランザクションで、再送確認、投稿権・完結判定、文字数検証、切り詰め、投稿保存と小説更新を一括確定します。SQLiteはDB全体で書き込みを直列化するため、小説単位の直列化要件を満たす一方、別の本への書き込みも短時間待機します。小規模な初期版の簡素さを優先した判断です。

DBの主な構造：

- `participants`：サーバー発行の匿名ID。
- `novels`：タイトル、上限、合計文字数、確定連番、作成日時。
- `posts`：小説・参加者・連番・冪等性キー・元原稿・掲載本文・掲載文字数・確定結果。

通常投稿は `is_admin = 0` の部分一意インデックス `(novel_id, participant_id)` で一冊一回に制限します。管理者投稿はこの回数制限を除外しますが、`(novel_id, sequence)` と `(novel_id, participant_id, request_key)` の一意制約は共通です。保存済み結果を再送時に返すため、後続投稿や完結後の再送も同じ結果になります。同じキーで原稿を変えた場合は409です。失敗・却下では投稿レコードを残さず、投稿権を消費しません。削除は本と全投稿を一つのトランザクションで削除します。

本文とタイトルはDOMの `textContent` で表示します。ユーザー入力をHTMLへ挿入しません。APIのSQLはプレースホルダーを使用し、JSON送信・Origin検証・CSPも設定しています。

## 匿名参加と既知の制限

Cookie削除、別ブラウザ、プライベートブラウズでは別参加者になります。「同一人物」を厳密には識別できません。フィンガープリントやIPによる人物判定は行いません。同じCookieを使う別タブは同じ参加者です。

localStorageが利用できない環境では警告を表示しますが、再読込後の原稿復元は保証できません。端末の保存領域を消去すると下書きも消えます。送信した元原稿（未掲載部分を含む）は再送確認と本人への結果表示のためDBにも保存されます。他の参加者に返す本文は掲載部分だけです。

タイトル一覧のページ分割や通知の差分配信は初期版では未実装です。現状は一覧と対象作品を再取得する構成で、大量の本・大人数の同時閲覧を前提にした負荷検証は未実施です。
